# 奨也の道（SHOYA'S ROAD）開発設計

2026-10-09 作成。開発指示書（`docs/開発指示書.md`）と最初のプラン（`プラン.md`）をもとに決めた設計。

## 1. 既存環境の確認（STEP 1）

- 2026-10-09 時点でコードは無し。`プラン.md`（2026-10-08 のたたき台）だけがあった。
- → 新規開発。指示書どおり Next.js + TypeScript + Tailwind + Recharts + PWA。
- Supabase は未契約・未設定 → **まずは端末内保存（localStorage + IndexedDB）で動く試作品**を作り、後から Supabase に差し替えられるようにデータ層を分離する。

## 2. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| フレームワーク | Next.js 16（App Router）`output: "export"` | 静的ファイルになるので GitHub Pages（すずドリルと同じ）で無料公開できる。サーバー不要 |
| 言語 | TypeScript（strict） | 指示書どおり |
| CSS | Tailwind v4 | 指示書どおり |
| グラフ | Recharts | 指示書どおり |
| データ | `src/lib/store`（localStorage に JSON 1本、`shoya.road.v1`）＋ `src/lib/media`（写真・動画は IndexedDB） | 設定不要・0円・オフラインでも動く |
| 将来の同期 | `DataStore` インターフェース（`load / save`）を Supabase 版に差し替える | iPhone と iPad の記録を合わせる課題に対応 |
| PWA | `app/manifest.ts` ＋ `public/sw.js`（アプリの殻をキャッシュ） | ホーム画面に追加して全画面で使う |
| 公開 | GitHub Pages（`basePath` は環境変数 `NEXT_PUBLIC_BASE_PATH` で切替） | push で自動公開 |

## 4. データ設計（`src/lib/types.ts`）

指示書のテーブル名をそのまま型名にしている（Supabase に移す時はこの型が各テーブルの行になる）。

| 型 | 主なフィールド | 備考 |
|---|---|---|
| `PlayerProfile` | name, nickname, number, bats, throws, avatar（キャラ設定）, photoId, dreamText, goalThisYear, goalNextYear | 1件 |
| `PracticeMenu` | id, name, icon, category（swing/fielding/throwing/footwork/running/stretch/quiz/free）, unit（count/min）, defaultTarget, xp, active, order | 保護者が編集 |
| `PracticeRecord` | id, date, menuId, amount, memo, measured?（catchOk/catchTry, throwOk/throwTry, run20m） | 1日1メニュー1件 |
| `MissionCompletion` | key=`date:menuId`, xpGranted | **二重付与防止の鍵** |
| `XpTransaction` | id, date, amount, source, uniqueKey | uniqueKey が同じものは2度入らない |
| `GameRecord` | date, opponent, result, score, pa, ab, hits, rbi, runs, steals, goodPlay, reflection, didWell, mediaIds | |
| `Goal` | id, order, title, detail, achievedAt, mediaIds, comment | ロードマップ |
| `Achievement` | id, unlockedAt | 定義は `data/achievements.ts` |
| `PlayerInventory` | itemId, acquiredAt, equipped | 定義は `data/items.ts` |
| `MediaAsset` | id, kind（photo/video）, type, date, comment, tag | 実体は IndexedDB |
| `QuizAttempt` | date, questionId, correct | 1日3問 |

## 5. ゲームロジック（`src/lib/game.ts`）

- XP：メニューごとに設定（既定：素振り30／ゴロ捕球40／キャッチボール30／足さばき30／走塁30／ストレッチ15／クイズ全問正解20／自由練習20／週間目標100）
- レベル：Lv n→n+1 に必要な XP ＝ `100 + (n-1)×25`。XP は減らない＝レベルは下がらない
- 育成ステータス（0〜100）：練習の種類ごとに少しずつ上がる（ゲームの値。実測とは別物と明記）
- メダル：記録が変わるたびに条件をチェックし、新しく満たしたものを獲得＋演出
- アイテム：レベルで解放。装備するとキャラに描画
- 連続記録：練習した日または「きょうは休み」の日が続いた日数。切れても画面に「切れた」とは出さない
- 1日の上限：同じ日の同じメニューは1回だけ XP。追加の練習は記録には残る（回数は合算）

## 6. 保護者と子どもの権限

- 保護者画面は 4桁 PIN（端末内）。初回に設定
- 子どもの画面には：ペナルティ、未達の数字、ネガティブな文言を出さない
- 公開プロフィール・SNS・チャットは作らない。写真・動画は端末内のみ

## 7. 実装の優先順位

1. 土台（型・store・レイアウト・キャラ）
2. オープニング／ホーム／マイ選手／ミッション／XP・レベル／履歴／グラフ／ロードマップ／メダル／パパの応援（MVP）
3. 試合／動画／クイズ／アイテム装備／ご褒美
4. 品質確認（型チェック・lint・build・ブラウザ確認）
5. 公開準備（README、GitHub Pages）
